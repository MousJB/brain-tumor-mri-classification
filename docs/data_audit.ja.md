# データ監査（2026 年 10 月）

[English](data_audit.md) · [README に戻る](../README.ja.md)

データセットは [MedVision QA](https://github.com/MousJB/medvision-qa) の重複検出モジュールで監査
しました（スクリプト `experiments/brain_mri/audit_mri_bt.py`、結果は `experiments/brain_mri/mri_bt_audit/`）。
対象は元の Training（5,712 枚）と Testing（1,311 枚）で、「Challenging」セットは除外しています。

## 所見

| 所見 | 値 |
|---|---|
| Training にバイト単位で同一のコピーがある Testing の画像 | **1,311 枚中 216 枚（16.5%）** |
| — うち髄膜腫 / 腫瘍なし / 下垂体腫瘍 | 106 / 105 / 5 |
| ラベルが異なる完全重複 | 0 |
| ラベルが異なる準重複（知覚ハッシュ、距離 ≤ 4） | 50。確認した 24 ペアはすべて異なる画像（誤検出） |
| 公開データセット figshare（Cheng ら）の画像に近い画像 | 1,704 |

## わかること

テストセットの 6 分の 1 は学習中にすでに使われています。したがって、この分割での評価は、一部が
学習データでの評価になっています。README に示した精度はおそらく楽観的ですが、この偏りの大きさは
測定していません。

## わからないこと

ファイルが同一であることは画像が同一であることを示しますが、患者が同一であることは示しません。
データセットに患者 ID がないため、同じ患者の別のスライスが Training と Testing に分かれて入って
いるかどうかは確認できず、実際の重なりはさらに大きい可能性があります。figshare との一致は、この
データセットに figshare の画像が含まれていることと矛盾しませんが、それを証明するものではありません。

## 公正な評価に必要なこと

患者単位の分割です。MedVision QA では、患者 ID を持つ figshare データセットでこれを行っています
（独立したテスト用患者 64 人、学習前に定めた受入基準、患者単位のブートストラップ信頼区間）。そこで
再学習した ResNet18 のマクロ F1 は 0.923 [0.867; 0.964] でした。これは別のモデル・別のタスク
（3 クラス、「腫瘍なし」なし）であるため、このリポジトリの結果とは直接比較できません。
